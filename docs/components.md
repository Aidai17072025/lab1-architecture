\# Описание компонентов Library Management System



\## Назначение компонентов



Library Management System использует трёхуровневую клиент-серверную архитектуру: уровень представления, уровень приложения и уровень данных.



| Компонент | Назначение | Технология | Взаимодействует с |

|---|---|---|---|

| Читатель (браузер) | Позволяет искать книги, просматривать каталог и управлять собственными бронированиями. | Веб-браузер | Frontend (React SPA) |

| Библиотекарь (браузер) | Позволяет управлять каталогом, выдавать книги и регистрировать возвраты. | Веб-браузер | Frontend (React SPA) |

| Администратор (браузер) | Позволяет управлять пользователями и назначать им роли. | Веб-браузер | Frontend (React SPA) |

| Frontend (React SPA) | Отображает интерфейс приложения, принимает действия пользователей и отправляет запросы серверу. | React, JavaScript | Backend NestJS (HTTPS, JSON) |

| Backend NestJS (модульный монолит) | Обрабатывает запросы, выполняет бизнес-логику, проверяет права доступа и организует работу с базой данных. | NestJS, TypeScript | Frontend (HTTPS, JSON), PostgreSQL (SQL) |

| Авторизация | Выполняет регистрацию и вход пользователей, проверяет их учётные данные и создаёт токены доступа. | NestJS | Пользователи, Проверка прав, PostgreSQL через ORM |

| Пользователи | Управляет учётными записями и ролями читателей, библиотекарей и администраторов. | NestJS | Авторизация, Проверка прав, PostgreSQL через ORM |

| Книги | Управляет каталогом, информацией об авторах и экземплярах книг, предоставляет поиск. | NestJS | Бронирования, Выдача и возврат, PostgreSQL через ORM |

| Бронирования | Проверяет доступность книг, создаёт и отменяет бронирования, не допускает конфликтующих броней. | NestJS | Книги, Пользователи, PostgreSQL через ORM |

| Выдача и возврат | Регистрирует выдачу книг читателям, сроки возврата и завершение выдачи. | NestJS | Книги, Пользователи, PostgreSQL через ORM |

| Проверка прав (RBAC) | Проверяет роль пользователя и разрешает выполнять только доступные ему операции. | NestJS Guards | Авторизация, все защищённые модули |

| Controller | Принимает HTTP-запросы и передаёт данные соответствующим сервисам. | NestJS Controllers | Frontend, Service |

| Service | Выполняет бизнес-логику, проверки и обработку данных приложения. | NestJS Services | Controller, ORM, другие модули |

| ORM | Обеспечивает взаимодействие серверного приложения с базой данных и выполнение операций чтения и записи. | Prisma ORM | Service, PostgreSQL |

| База данных PostgreSQL | Хранит пользователей, роли, книги, авторов, экземпляры, выдачи и бронирования. | PostgreSQL | Только Backend через ORM (SQL) |



\## Принцип взаимодействия



Пользователь открывает приложение в браузере и выполняет действие через React SPA. Frontend отправляет HTTPS-запрос в Backend NestJS с данными в формате JSON. Контроллер принимает запрос, модуль проверки прав контролирует доступ, а сервис выполняет необходимую бизнес-логику. Для чтения или изменения информации сервер использует ORM, который взаимодействует с PostgreSQL. После обработки Backend возвращает ответ, и React обновляет интерфейс пользователя.



\## Основные архитектурные принципы



1\. Приложение разделено на три уровня: представление, приложение и данные.

2\. Frontend не имеет прямого доступа к PostgreSQL.

3\. Проверка прав и важных данных выполняется на сервере.

4\. Backend построен как модульный монолит NestJS.

5\. Каждый модуль отвечает за свою часть функциональности.

6\. Данные хранятся централизованно в PostgreSQL.
