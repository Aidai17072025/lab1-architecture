\# Жизненный цикл HTTP-запроса



\## Сценарий UC2 — Читатель бронирует книгу



\### 1. Действие пользователя

Читатель открывает каталог библиотеки, выбирает доступную книгу и нажимает кнопку «Забронировать». React SPA формирует запрос на создание бронирования.



\### 2. DNS

Браузер определяет IP-адрес сервера `library.example.com` через DNS, если адрес ещё не сохранён в кэше. Полученный IP-адрес используется для подключения к серверу.



\### 3. Установка соединения TCP/TLS

Браузер устанавливает TCP-соединение с сервером и выполняет TLS-рукопожатие. После этого обмен данными происходит по защищённому протоколу HTTPS.



\### 4. Отправка HTTP-запроса

Frontend отправляет POST-запрос на адрес `/api/reservations`.



Метод: `POST`



Путь: `/api/reservations`



Заголовки:



```http

Content-Type: application/json

Authorization: Bearer <токен\_читателя>

```



Тело запроса:



```json

{

&#x20; "bookId": 15

}

```



Здесь `bookId` — идентификатор выбранной книги. Идентификатор читателя сервер определяет по токену авторизации.



\### 5. Приём запроса

Backend NestJS принимает HTTP-запрос и направляет его в контроллер модуля «Бронирования».



\### 6. Обработка запроса в Backend

Модуль «Авторизация» проверяет токен, а Guards (RBAC) проверяет роль пользователя. Controller передаёт запрос в Service модуля «Бронирования». Service обращается к модулю «Книги», проверяет наличие доступного экземпляра и отсутствие конфликтующего бронирования.



\### 7. Обращение к базе данных

Service использует Prisma ORM для обращения к PostgreSQL. Сервер проверяет доступный экземпляр книги, создаёт запись в таблице `reservations` и закрепляет экземпляр за бронированием в одной транзакции. Это предотвращает одновременное бронирование одного экземпляра двумя читателями.



\### 8. Ответ сервера

После успешного сохранения Backend возвращает HTTP-ответ со статусом `201 Created`.



Формат ответа — JSON:



```json

{

&#x20; "reservationId": 101,

&#x20; "bookId": 15,

&#x20; "status": "active",

&#x20; "message": "Книга успешно забронирована"

}

```



Если свободных экземпляров нет, сервер возвращает ошибку `409 Conflict`.



\### 9. Обновление интерфейса

React получает ответ от Backend и обновляет интерфейс. Читатель видит сообщение «Книга успешно забронирована», а созданная бронь появляется в разделе «Мои бронирования».



\## Итог



Запрос проходит через React SPA, Backend NestJS и PostgreSQL. Сервер самостоятельно проверяет авторизацию, права пользователя и доступность книги. Клиент не подключается к базе данных напрямую.
